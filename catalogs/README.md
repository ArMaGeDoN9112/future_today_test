# Локальные справочники

Получены и проверены 22 октября 2026 года. Рабочий снимок:
`snapshots/2026-10-22.json`. Он поставляется в Git и читается при запуске;
`npm install` и `npm start` не загружают справочники. Исходники в `sources/`
нужны только разработчику для воспроизводимой подготовки и проверки происхождения.

## Города: 1117 записей

Источник: Evgeniy Pogrebnyak и Kirill Artemov,
[1117 Russian cities…](https://doi.org/10.5281/zenodo.5151423), версия 0.4.0,
опубликованная 1 августа 2021 года. Данные основаны на публикациях Росстата
с оценкой населения на 1 января 2020 года. Сохранены фактически полученные
[CSV](https://zenodo.org/records/5151423/files/towns.csv?download=1)
и [паспорт](https://zenodo.org/api/records/5151423) с `license.id = cc-by-4.0`.

Лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) разрешает
повторное использование с указанием авторов, источника, лицензии и изменений.
Изменения: оставлены `fias_id → id`, `city → name`, `region_name → region`;
данные отсортированы по ID. Сохранены все строки, без ручного дополнения.
Устойчивый ID — ФИАС UUID, а не позиция или название.

Охват и ограничения: 1117 городов в 82 уникальных значениях `region_name`;
это исторический снимок, не актуальная выгрузка ГАР. Посёлки, сёла и зарубежные
города не включаются. Источник не выделяет некоторые города внутри больших
городов (например, Сестрорецк и Щербинку); автономные округа внутри Тюменской
области в этом снимке объединены с ней. Географическая классификация сохранена
как в источнике, включая Крым и Севастополь. Названия с ё могут быть записаны
через е; поиск учитывает оба варианта. Переименования и изменения после даты
исходных данных могут отсутствовать. Полнота на 2026 год не утверждается.

## Вузы: 438 записей

Источник: [Wikidata Query Service](https://query.wikidata.org/), запрос
`sources/universities.rq`, фактический ответ сохранён в `sources/universities.json`.
Формат — SPARQL Results JSON. Структурированные данные Wikidata доступны по
[CC0](https://www.wikidata.org/wiki/Wikidata:Licensing), свободное повторное
использование разрешено. Авторы данных — участники Wikidata.

Правила отбора: `P17 = Q159` (Россия), `P31/P279* = Q3918` (университет и
его подтипы), русская метка, отсутствие `P576` (даты прекращения).
Запрос вернул 444 записи. При подготовке исключаются названия, содержащие
«колледж», «техникум», «факультет» без учёта регистра. В полученном снимке это
одна запись: `Q4221651`, Кировский лесопромышленный колледж, СПО вне объёма.
Также применён проверяемый список `sources/university-exclusions.json` с причинами
и ссылками: здание университета (`Q110279659`), Казанское суворовское (`Q4207865`)
и Нахимовское военно-морское (`Q4314683`) училища общего образования, школы
дополнительного образования «Индустрия» (`Q141460888`) и Московская школа
нового кино (`Q18786086`), лицензии которых не подтверждают высшее образование.
`item → id` (QID), `name → name`; сортировка по ID, без объединения организаций
с одинаковыми названиями. Идентификатор не зависит от переименования.

Ограничения: это широкий справочник российских вузов, **не полный реестр
действующих лицензий**. Академии и институты, не отнесённые в Wikidata к
подтипам университета, организации без русской метки/страны и неописанные
филиалы могут отсутствовать. Отсутствие даты прекращения не доказывает,
что организация работает: возможны устаревшие названия, дубликаты сущностей,
неотмеченные реорганизации и ошибки классификации. Наличие записи не
подтверждает статус студента или аккредитацию вуза. Направления с вузами не связаны.
Если нужного значения нет, будущий интерфейс должен предлагать связаться
с организатором; произвольный текст не становится допустимым значением.

## Проверенные, но не использованные кандидаты

ГАР ФНС требует отдельной обработки значительно большего адресного набора.
Для этого тикета выбран компактный опубликованный CSV с проверенным паспортом.
Раздел открытых данных Минобрнауки при проверке перенаправлял на страницу
технических работ. Каталог Hipo доступен как JSON под MIT, но найденные 308
российских записей преимущественно имеют английские названия. Исторический
мониторинг вузов и недоступная ранее выгрузка Рособрнадзора не выдаются за
полученный актуальный реестр. От этих кандидатов данные в снимок не добавлялись.

## Повторная подготовка без сети

Только для разработчика, PowerShell 7; для работы приложения он не требуется:

```powershell
pwsh -NoProfile -File scripts/prepare-catalogs.ps1 -Version 2026-10-22
```

Скрипт читает сохранённые CSV/JSON и список исключений, проверяет обязательные значения,
регионы, идентификаторы и уникальность ID. Повторный запуск должен давать
тот же снимок; попытка заменить уже существующую версию другими данными
завершается ошибкой. Входные файлы идентифицируются SHA-256:

| Файл | SHA-256 |
| --- | --- |
| `towns.csv` | `97F08B0E7A8259FEC7643B48C07330E1475A8F5996A95438DE1C82D79435261A` |
| `universities.json` | `C69F5055F774FB5102C73EF54C4CBCDBD0D13A2F3D1F2A7666A1D2D112E81D6F` |
| `university-exclusions.json` | `8EBF4AA28CCD5A1B5E284ED0A2BCC0FB875A289A82E9D1B959FEF33840AABD46` |

## Обновление разработчиком

1. Выбрать и проверить новую версию источников: фактическую загрузку, формат,
   лицензию, происхождение и охват. Для того же источника городов скачать CSV
   и паспорт по ссылкам выше (для новой версии заменить номер записи Zenodo).
   Для вузов выполнить сохранённый запрос:

   ```powershell
   $query = Get-Content catalogs/sources/universities.rq -Raw -Encoding utf8
   $url = 'https://query.wikidata.org/sparql?format=json&query=' + [uri]::EscapeDataString($query)
   Invoke-WebRequest $url -Headers @{'User-Agent'='FormsCatalog/1.0'} -OutFile catalogs/sources/universities.json
   ```

2. Сохранить новые исходники в Git, записать дату, SHA-256, лицензию и изменения
   правил в этом документе. Не выдумывать пропущенные значения. Проверить
   удалённые/добавленные ID и переименования; падение количества записей,
   спорные совпадения и смена классификации требуют содержательной проверки.
3. Запустить скрипт с **новой** версией `YYYY-MM-DD`. Он создаёт новый файл
   `snapshots/<version>.json`. Не редактировать и не удалять старые снимки.
   При смене поставщика сопоставлять сущности вручную с прежними ID;
   не переиспользовать ID для другой сущности, не генерировать ID из названия.
4. В `src/catalogs.js` переключить `catalogVersion` на новый проверенный снимок.
   Обновить HTTP-тесты (версию, количество и примеры), выполнить
   `npm run typecheck` и `npm test`, затем закоммитить данные и код вместе.

Достоверность старых откликов: снимки неизменяемы и сохраняются с версией.
Будущая реализация откликов (тикет 04) должна сохранять версию справочника
и выбранную запись `{ id, name, region? }` на момент принятия; отображать
прежний ответ из сохранённых значений, а не заново трактовать его по текущему
справочнику. Старый ID не становится другим вузом/городом, переименованный
ответ не меняется задним числом, удаление из нового справочника не удаляет
ранее принятый ответ. Новые отклики проверяются по активному снимку через
`getCatalogEntry`, а не по результатам поиска. Хранение откликов этот тикет
не реализует. Обновлений при запуске и редактора для менеджера нет.
