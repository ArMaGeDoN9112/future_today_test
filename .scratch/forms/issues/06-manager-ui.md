# 06: Интерфейс менеджера

**What to build:** менеджер без авторизации работает в административной панели: создаёт форму, редактирует черновик, публикует ссылку, управляет приёмом, просматривает отклики и аналитику. Интерфейс использует уже реализованную серверную логику.

**Blocked by:** 05 — Попытки заполнения и аналитика. Эта зависимость также закрепляет согласованный порядок: весь серверный этап завершается до начала UI.

**Status:** done

- [x] Административная панель доступна по `/admin` без авторизации; интерфейс на русском языке.
- [x] Менеджер видит список форм и различает черновики, опубликованные и закрытые формы, может открыть нужную форму.
- [x] Конструктор позволяет задать название, добавлять, изменять и удалять поля черновика, выбирать согласованные типы, подписи и обязательность, задавать варианты одного выбора.
- [x] Город, вуз, направление, уровень и курс добавляются по желанию менеджера. Наличие одного справочного поля не заставляет добавлять остальные.
- [x] Публикация показывает полученную уникальную ссылку и явно сообщает о фиксации содержания. Опубликованная форма недоступна для редактирования, в том числе после закрытия или повторного открытия.
- [x] Доступны закрытие и повторное открытие приёма. Ссылка и полученные отклики сохраняются; состояние в интерфейсе соответствует ответу сервера.
- [x] Менеджер видит список откликов выбранной формы, их количество и ответы по всем полям. Справочные значения отображаются понятными названиями, а не только техническими идентификаторами.
- [x] Отображаются просмотры, начала, отправленные отклики, заполнения в процессе, незавершённые заполнения и последние активные поля. Поясняются правило 30 минут и ограничение интерпретации последнего поля.
- [x] Загрузка, сохранение, ошибки и отсутствие откликов имеют понятные состояния. Пользовательские подписи и ответы не исполняются как разметка или скрипты.
- [x] Элементы управления имеют видимые подписи и доступны с клавиатуры; действия используют готовые серверные операции, а не дублируют бизнес-правила только в UI.
- [x] Браузерные проверки покрывают создание и изменение черновика, публикацию и блокировку редактирования, управление приёмом, отображение откликов и аналитики. Недостающие для проверки данные допустимо подготовить через согласованный HTTP-интерфейс, не через внутренности хранилища.


## Comments

Реализована панель менеджера `/admin` на HTML/CSS/JavaScript без зависимостей времени выполнения. Она использует существующие HTTP-операции: сохранение черновика, публикацию, закрытие и повторное открытие, чтение откликов и аналитики. Несохранённые изменения блокируют публикацию до сохранения. Пользовательские подписи и ответы выводятся как текст; справочные ответы показывают сохранённые названия, регион, код и уровень.

Проверки: `npm run typecheck` и `npm test` — 30 тестов пройдены, включая три браузерных сценария Playwright. Проверены все статусы в списке, создание/изменение/удаление полей, независимость справочных полей, ошибки и повторная загрузка, публикация и блокировка редактирования, сохранение ссылки и откликов при управлении приёмом, пять показателей и граница 30 минут, безопасный вывод разметки. Данные откликов и попыток подготовлены через HTTP; часы изменяются только в изолированном тестовом процессе.

Выполнено ревью двумя агентами: Standards — 0 замечаний, Spec — 0 замечаний. Визуально проверены конструктор и опубликованная форма, экран 375px и альбомная ориентация, reduced motion и масштаб текста 200%.
