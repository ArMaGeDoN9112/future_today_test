# Сервис форм отклика

Серверный жизненный цикл форм и локальные справочники (тикеты 01–03). Node.js 20 или новее.
Из корня проекта:

```sh
npm install
npm start
```

Сервер слушает `localhost:3000`. Для другого порта в PowerShell:

```powershell
$env:PORT = '3001'
npm start
```

`PORT=0` выбирает свободный порт. Фактический адрес выводится при запуске.
При работе не нужны внешние сервисы, СУБД или интернет. Пакеты разработки
используются только для проверки типов; у сервера нет npm-зависимостей.
UI, `/admin`, отклики и аналитика реализуются следующими тикетами.

## HTTP-контракт

Все ответы — JSON в UTF-8. Тела создания и изменения требуют
`Content-Type: application/json`, предел — 1 МиБ. Авторизации нет;
сервер привязан к localhost. URL ниже относительны к адресу сервера.

| Метод и URL | Результат |
| --- | --- |
| `GET /api/forms` | `200`, массив всех форм |
| `POST /api/forms` | `201`, созданный черновик; тело `{ "title": "Стажировка", "fields": [] }` |
| `GET /api/forms/:id` | `200`, форма для менеджера |
| `PATCH /api/forms/:id` | `200`, обновлённый черновик; тело с `title`, `fields` или обоими свойствами |
| `POST /api/forms/:id/publish` | `200`, опубликованная форма с `publicUrl` |
| `POST /api/forms/:id/close` | `200`, закрытая форма |
| `POST /api/forms/:id/reopen` | `200`, повторно открытая форма |
| `GET /forms/:token` | `200`, содержание опубликованной или закрытой формы |
| `GET /api/catalogs/cities?q=Киров` | `200`, `{ version, items: [{ id, name, region }] }` |
| `GET /api/catalogs/cities/:id` | `200`, `{ version, item: { id, name, region } }` |
| `GET /api/catalogs/universities?q=университет` | `200`, `{ version, items: [{ id, name }] }` |
| `GET /api/catalogs/universities/:id` | `200`, `{ version, item: { id, name } }` |

Переходы состояния не требуют тела запроса. Допустима только цепочка
`draft → published → closed → published`, последние два перехода можно повторять.
Повторная публикация и переход в текущее состояние возвращают `409`.

Пример созданного черновика (идентификатор генерирует сервер):

```json
{
  "id": "a5e01031-e9ce-4455-93e6-a465f614aaf9",
  "title": "Стажировка",
  "fields": [
    { "id": "email", "type": "email", "label": "Почта", "required": true },
    { "id": "format", "type": "single_choice", "label": "Формат", "required": false, "options": ["Очно", "Удалённо"] }
  ],
  "status": "draft",
  "publicUrl": null
}
```

`title` и подпись `label` — непустые строки. У каждого поля обязательны
`id`, `type`, `label`, `required` (boolean). Менеджер задаёт уникальные в пределах
формы строковые `id` и сохраняет их при изменении подписи, типа или обязательности.
Чтобы добавить, изменить, удалить или переставить поля, передайте весь новый
массив `fields` в PATCH. Отсутствующее свойство в PATCH остаётся прежним;
переданный массив заменяет предыдущий целиком. Пустой массив допустим.

| `type` | Поле |
| --- | --- |
| `short_text` | Короткий текст |
| `long_text` | Длинный текст |
| `email` | Email |
| `single_choice` | Выбор одного варианта |
| `city` | Город проживания |
| `university` | Вуз |
| `study_direction` | Направление обучения |
| `study_level_course` | Уровень и курс обучения (одно составное поле) |

Только `single_choice` требует `options`: непустой массив непустых строк,
без повторов после удаления пробелов по краям. Неизвестные свойства формы
и полей отклоняются. Для справочных полей форма пока хранит только метаданные.

Публикация присваивает отдельный случайный `publicUrl`, например
`/forms/61dffbe7-2199-40e0-aec8-e339ed9aad2d`. Это публичная ссылка,
её можно объединить с origin сервера (`new URL(form.publicUrl, origin)`).
Черновик не имеет публичной ссылки; запрос по неизвестному token или по id
черновика возвращает `404`. После публикации PATCH возвращает `409`,
в том числе после закрытия и повторного открытия. Ссылка и содержание неизменны.
Публичное чтение закрытой формы возвращает её содержание, `status: "closed"`
и `message: "Приём завершён"`; потребитель должен показать завершение приёма.

Ошибка имеет вид `{ "error": "Понятное сообщение" }`:

| Статус | Причина |
| --- | --- |
| `400` | Некорректный JSON или структура формы |
| `404` | Неизвестный маршрут, форма или публичная ссылка |
| `405` | Неподдерживаемый метод |
| `409` | Запрещённое редактирование или переход состояния |
| `413` | Тело больше 1 МиБ |
| `415` | Неподходящий Content-Type |
| `500` | Ошибка обработки или записи; успех не подтверждён |

## Справочники городов и вузов

В поставку включён локальный снимок `2026-10-22`: 1117 городов с регионами
и 438 вузов. Это широкие выборки с ограничениями охвата, а не гарантированно
полный актуальный реестр. Происхождение, лицензии, правила отбора и обновления
описаны в [catalogs/README.md](catalogs/README.md).

Поиск `q` ищет подстроку названия без учёта регистра и различия е/ё;
пробелы по краям убираются. Отсутствующий или пустой `q` возвращает весь
справочник, без скрытого ограничения числа результатов. Параметры URL нужно
кодировать через `URLSearchParams`. Результат без совпадений — `200` с `items: []`.
Неизвестный ID или справочник — `404` с `error`; методы кроме GET — `405`.
У города всегда есть `region`, в том числе у одноимённых городов.

`src/catalogs.js` экспортирует `catalogVersion`, `searchCatalog(kind, query)`
и `getCatalogEntry(kind, id)` для `kind = 'cities' | 'universities'`.
Проверка будущих откликов должна вызывать `getCatalogEntry` по переданному ID:
она читает весь тот же снимок и возвращает `undefined` для неизвестного значения.
Результаты поиска не заменяют эту проверку. Записи в памяти неизменяемы.
Снимок читается относительно кода приложения, независимо от рабочего каталога;
повреждённый или отсутствующий файл прерывает запуск с ошибкой.

## Направления и курсы обучения

Локальный снимок `2026-10-22-study.json` содержит 490 записей ОКСО:
181 бакалавриата, 195 магистратуры и 114 специалитета, а также 11 вариантов
уровня и курса. Это полный отбор трёх уровней из сохранённой базовой редакции
ОКСО ОК 009-2016, без гарантии учёта последующих изменений.
Источник, условия использования, ограничения и воспроизводимое обновление —
в [catalogs/README.md](catalogs/README.md).

| GET | Результат |
| --- | --- |
| `/api/catalogs/study-directions?q=09.03.01` | Поиск по коду или названию |
| `/api/catalogs/study-directions/okso-2.09.03.01` | Запись по ID |
| `/api/catalogs/study-courses` | Все 11 вариантов, без обязательного вуза или направления |
| `/api/catalogs/study-courses?directionId=okso-2.09.03.01` | Курсы уровня выбранного направления |
| `/api/catalogs/study-courses/bachelor-4plus` | Вариант курса по ID |

Ответы имеют прежнюю оболочку `{ version, items }` или `{ version, item }`.
Направление: `{ id, code, name, level }`; код отображается без префикса области
образования ОКСО, например `09.03.01`; ID сохраняет полный код `okso-2.09.03.01`.
Уровни: `bachelor` (бакалавриат), `master` (магистратура), `specialist` (специалитет).
Поиск учитывает регистр и е/ё так же, как остальные справочники.

Курс: `{ id, name, level, course }`, например
`{ "id": "bachelor-4plus", "name": "Бакалавриат — 4 курс и выше (4+)", "level": "bachelor", "course": "4+" }`.
Допустимы бакалавриат 1, 2, 3, 4+; магистратура 1, 2+;
специалитет 1, 2, 3, 4, 5+. Последняя группа включает все последующие курсы.
Неизвестный ID записи или `directionId` (включая пустой) возвращает `404`.
Вуз и направление не связываются. Экспорты `searchCatalog(kind, query, level?)`
и `getCatalogEntry(kind, id)` поддерживают также `study-directions` и `study-courses`.
Будущая отправка откликов должна проверять оба ID и совпадение `level` через эти
экспорты; HTTP-фильтрация сама по себе не заменяет проверку отклика.

## Хранение и проверки

Данные находятся в `data/forms.json` относительно рабочего каталога. При запуске
из корня это каталог внутри проекта; он создаётся при первом сохранении
и исключён из Git. Не удаляйте его при обновлении. Для резервной копии остановите
сервер и скопируйте `data/`. Некорректное или недоступное существующее хранилище
прерывает запуск, а не заменяется пустым.

Каждое изменение записывается во временный файл с `fsync`, затем атомарно
заменяет основной файл. Только после этого обновляется состояние в памяти
и отправляется успешный ответ. Обработка изменения и запись синхронны:
параллельные HTTP-запросы одного процесса не теряют формы. PATCH применяет
изменения к актуальному состоянию после получения тела запроса. Если несколько
запросов меняют одно свойство, остаётся последнее успешно сохранённое значение.

Запускайте один процесс на один каталог `data/`. Совместный доступ нескольких
процессов и большие объёмы потребуют транзакционного хранилища.

```sh
npm run typecheck
npm test
```

Тесты запускают отдельные реальные процессы на свободных портах, вызывают HTTP
и проверяют восстановление после остановки процесса. Для проверки отказа записи
временно блокируется каталог данных тестового экземпляра; внутренний формат
файла не читается. Рабочие данные проекта не используются.
